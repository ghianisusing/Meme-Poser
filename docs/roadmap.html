Meme Poser · improvement map · Nov 2026

Strike a pose, get the meme

The game watches your body, works out which pose you're doing, and shows the meme that goes with it. A gallery of every meme stays on screen so players know which poses to try. This map covers two tracks: recognizing many poses reliably, and making the gallery and reveal feel good. Based on pose_detection.py and face_detector.py on branch chore/python-venv.

Where it stands

What the code does today

MediaPipe finds 33 body points per frame. One rule then checks for one pose: both wrists within 120 pixels of the ears. If it passes, a separate window opens with the meme. The reveal idea works; the recognition behind it is what limits the game.

  • High
    It can only recognize one pose. The rule for "hands behind head" is written into the main loop, and current_pose is fixed. There's no way to ask "which of my memes is this?"pose_detection.py:36, 103–108
  • High
    How far you stand changes the result. 120 pixels is a lot when you're close and very little when you're far. It also changes with webcam resolution.pose_detection.py:107
  • High
    Wrong poses trigger the meme. Covering your ears, or resting your chin on your hands, also passes. Elbows, which define this pose, aren't checked. Ears are often hidden in this pose and visibility isn't checked. With more memes, this turns into the wrong meme appearing.pose_detection.py:89–108
  • Medium
    The meme window blinks. At the edge of the threshold the popup opens and closes every few frames. There's no smoothing and no "hold for a moment" rule.pose_detection.py:129–145
  • Medium
    The reveal is a separate window at a fixed spot. It's placed at x = 1450, which is off-screen on 1366 px laptops, and opening a new OS window each time feels clunky.pose_detection.py:133–135
  • Medium
    A missing image crashes before the error message. cv2.resize(cv2.imread(...)) fails on a missing file before the "Failed to load" check runs.pose_detection.py:24–34

Pipeline

How a frame should flow

Today

Webcam→ MediaPipe Pose→ wrist↔ear px distance→ < 120 ?→ open meme window

Target

Webcam→ Pose model→ visibility gate→ normalize body size + position→ classify: which pose, or none→ hold ~0.5 s→ reveal that pose's meme

The key change is the classifier: it compares your body to every pose in the library and picks the best one, or "none" if nothing is close enough. Adding a meme then means adding examples, not writing a new rule. The same pose library also feeds the on-screen gallery, so players always see which memes exist.

Sketch

The core of the classifier

Turn a frame into numbers that don't depend on where you stand: move the hips to the origin and scale by shoulder width.

# classifier.py
def normalize(lm):
    hip = midpoint(lm[L_HIP], lm[R_HIP])
    sw = dist(lm[L_SHOULDER], lm[R_SHOULDER])
    return np.array([
        ((p.x - hip.x) / sw, (p.y - hip.y) / sw)
        for p in lm[UPPER_BODY]
    ]).ravel()

Pick the closest recorded pose. Too far from everything means no meme.

def classify(vec, samples, max_dist=0.8, k=5):
    # samples: list of (pose_name, vector)
    d = sorted(
        (np.linalg.norm(vec - s), name)
        for name, s in samples
    )[:k]
    if d[0][0] > max_dist:
        return None
    return Counter(n for _, n in d).most_common(1)[0][0]
